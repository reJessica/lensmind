# 三人协作与联调

## AI 与文档规则

- 组员及其 AI 助手开始修改前，先阅读根目录 [AGENT.md](../AGENT.md)；[AGENTS.md](../AGENTS.md) 提供自动发现入口。
- 每次项目更新都要同步维护 [README.md](../README.md)，新增日期、更新人、修改内容与验证情况；影响功能说明或启动方式时，同时修改正文。
- 更新人使用实际姓名/团队昵称，AI 辅助时注明助手；身份未知时标记待补充，不代替他人署名。
- 同一任务的连续编辑可合并记录；新任务或后续独立更新另记，不覆盖组员历史记录。
- 此要求同样适用于仅修改配置、测试或文档的任务；只读咨询无需改文件。

## 组长：模型调试与后端接入

- 负责模型选型、提示词、参数和效果对比，优先调通文字指令理解与图像分析。
- 通过 Spring Boot 调用模型，向前端返回统一的解析结果、构图建议和人物指导；需要时在后端增加模型/视觉/语音服务。
- 当前已有 `ai/`、`api/AiController.java`、`resources/prompts/` 和验证脚本，继续在这些边界上调试；接入说明见 [MODEL_HANDOFF.md](MODEL_HANDOFF.md)。
- 将模型名称、提示词和参数独立管理，密钥仅通过服务端配置读取。
- 与组员一约定输入/输出格式、超时和错误反馈；前端规则解析仅作明确标注的占位或回退。
- 与组员二约定模型可获取的模拟原始帧、调整意图和动作完成状态，验证小步调整后的画面变化。
- 人物框、姿态、稳定性等能力按实际效果逐步接入；未实现时保留明确的提示或手动确认，不伪造分析结果。
- 首阶段交付：可由后端调用的模型、配置/启动说明、请求响应样例和一组固定测试场景的效果记录。

## 组员一：前端与整体体验

- 维护 `static/index.html`、`css/`、`js/app.js`、`js/crop.js`、`js/commands.js` 和 `js/api.js`。
- 完善取景、构图设置、语音/文字输入、指导、拍摄倒计时、裁剪编辑、照片预览与下载。
- 对接组长提供的模型接口，显示识别文本、分析结果和执行反馈；模型在后端调用，前端不保存密钥。
- 可复用 `js/ai-client.js`；当前 `app.js` 尚未切换到新模型接口，需显式对接。UniAPI Whisper 已通过真实转写验证，云端 TTS 仍因上游满载未成功；不能把 MOCK 转写、提示音或本地测试语音显示成云端识别/合成成果。
- 对接组员二提供的模拟视频/原始帧、控制接口与设备状态，明确标注仿真模式。
- 负责页面侧整体体验与流程串联；根据设备状态和模型提供的判断决定是否允许拍照，尚无自动判断时明确提示。
- 明确预览与原始帧的像素映射，不把 UI 辅助线绘入原片；检查窄屏、停止、断连、倒计时取消等交互。
- 首阶段交付：能使用模型和仿真接口完成一轮拍摄、裁剪、下载的页面，并说明待接入项。

## 组员二：摄像头与机械臂仿真、模拟连接

- 当前负责仿真和模拟连接，真实 SO-101、末端摄像头及香橙派接入不作为本阶段必交任务。
- 基于 `DeviceGateway` 扩展模拟服务。目前提供二维固定场景及 MuJoCo SO-101 三维仿真。三维联调使用原始腕部帧和外部机械臂视角。
- 提供可由网页预览的模拟画面和可供模型分析/拍照的原始帧，说明分辨率、帧标识/时间戳、镜像情况和坐标方向。
- 在仿真环境中实现模拟连接、可支持方向的机位小步调整、回初始位和停止；让机位变化与模拟相机画面保持一致，暂不支持的动作明确拒绝。
- 校验模拟步长与工作范围，提供连接、执行、完成、停止和异常反馈；新增状态与字段先更新接口约定。
- 模拟断连、越界、停止取消等异常情形，停止后不继续执行待处理动作，恢复连接不自动重放旧动作。
- 向组长提供动作完成后的新画面，向组员一提供控制与状态接口，支持整条流程联调。
- 保留真实设备适配边界，后续使用配置区分仿真与实机；不得因开发或测试自动连接并驱动真实设备。
- 首阶段交付：仿真/模拟服务、启动说明、视频和原始帧接入方式、控制接口样例、动作范围与异常验证记录。

## 三人共同确认与联调顺序

1. 明确仿真方案、模拟相机画面来源、图像传输格式和部署方式；不预设一定使用某种仿真引擎。
2. 按 `API.md` 约定原始帧、图像坐标、模型输出、调整请求、任务标识和设备状态。
3. 先打通「模拟预览 → 页面按钮微调 → 状态反馈 → 停止」。
4. 再接入「用户指令 → 后端模型 → 仿真调整 → 新画面检查」。
5. 最后串联人物指导、倒计时拍摄、裁剪和下载，完成固定场景演示。
6. 主线稳定后，可在各自方向自由完善体验和扩展功能；影响公共接口时先同步，避免重复开发。

## Git 工作方式

- 组长固定使用 `ya.liu`，组员使用各自已有分支；同步最新主分支后继续开发，AI 不擅自为组长新增临时分支。
- PR 描述写清功能、接口变化、验证方式和待接入项；至少由另一位组员看过再合并。
- PR 必须包含 README 更新记录，并标注本次更新人。
- 修改公共接口先同步其他两人。API 文档与代码同时提交。
- 本地先运行 `./mvnw test`；涉及交互时手动验证下面的流程。

## 当前框架验收清单

- 打开首页，看到模拟模式、控制服务连接状态和模拟插画。
- 居中/左右构图、画幅比例和数字放大可用，裁剪操作不改变接口中的 x/y。
- 在三维仿真依次点击左转、前进、上升、抬头、右转、后退、下降、低头，检查机位数值分别更新，腕部取景和机械臂外部视角使用同一机位。二维模式的左移继续更新模拟坐标 X 和原始帧。
- 请求动作指导时，机位与拍摄禁用；手动确认完成后恢复。
- 3 秒倒计时拍照后生成缩略图；在倒计时中按停止/切换页面后台，不生成新照片。
- 停止后机位不可继续移动，回初始位后恢复。
- 照片编辑框支持拖动、比例、放大和撤销；原片与成片可独立下载。
- 断开控制服务后禁用拍摄/移动，恢复服务后自动重连。
- 麦克风不受支持/权限拒绝时，仍可输入文字；摄像头权限拒绝时返回模拟场景。
- 在窄屏检查控制区、照片编辑和停止入口。

模拟机位和新原始帧现可通过设备接口一起获取。后续仿真联调需验证模型实际消费新帧、引入待执行动作后的停止取消，以及模拟断连/越界的联调反馈。

真实硬件接入属于后续扩展，届时需另行设计校准、回零路径、真实限位/速度检查及硬件停止，并补充实机验收。目前的模拟演示不代表已满足完整硬件验收。
