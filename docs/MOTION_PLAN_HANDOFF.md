# 机械臂调整 JSON 对接

更新人：ya.liu（AI 辅助：Codex） · 2026-11-28

LLM 的一次回答拆成两个通道：`feedback` 显示给用户并由现有 Gemini TTS 播报；`controlPlan` 交给控制端。ASR 保持本地 Zipformer。两部分来自同一次 LLM 请求，不另调一次模型。

## 文件与字段

默认后端目录：`data/control-plans/`。文件名由后端生成：`lensmind-plan-<UUID>.json`。临时文件后缀 `.tmp`，写完再改为 `.json`；控制端只读取最终 JSON。示例：

```json
{
  "schemaVersion": "lensmind.motion.v1",
  "planId": "8432300d-894e-4851-b335-0ee9e95278c1",
  "createdAt": "2026-11-28T11:00:00Z",
  "expiresAt": "2026-11-28T11:01:00Z",
  "status": "PROPOSED",
  "executed": false,
  "sceneSha256": null,
  "actions": [{ "type": "MOVE", "direction": "LEFT", "step": 1 }]
}
```

时间为 UTC；有效期从后端生成文件开始 60 秒。`sceneSha256` 为本次取景 data URL 的 UTF-8 SHA-256，无图时为 null；不保存图像，不是设备 frameId。模型耗时期间画面可能已变化，执行前仍需读取新设备/相机状态。

`step=1` 表示现有设备接口的一次微调，由适配器解释实际单位。不能当作 1°、1mm 或一个编码器刻度。支持的意图方向如下，设备支持哪些方向由控制端判断：

| direction | 意图 |
| --- | --- |
| LEFT / RIGHT | 镜头左 / 右调整 |
| UP / DOWN | 镜头升 / 降 |
| FORWARD / BACKWARD | 镜头前进 / 后退 |
| PITCH_UP / PITCH_DOWN | 镜头抬头 / 低头 |

方向沿用既有相机控制接口，不是人物自身左右，也不直接映射为关节正负。当前 SO-101 实机桥只支持已采样的左右微转，其他方向必须拒绝；仿真支持范围与实机不同。

无移动需求时文件为 `status: "NO_ACTION"`、`actions: []`。数字放大、裁剪、人物摆姿、问句、否定指令和含义不清时都不应移动。文件没有反馈文本、密钥、串口、扭矩、脚本或关节角。

## 组员二读取与执行

当前交付到「生成、落盘、预览、下载」；尚未实现监控目录并自动执行的消费者。读取一个文件后：

1. 校验 schemaVersion、planId、expiresAt、PROPOSED 状态与动作白名单，NO_ACTION 直接忽略；同一 planId 最多执行一次。
2. 检查是否收到停止、设备是否连接/静止、是否允许接管、当前工作空间和限位、取景是否仍适用。过期或状态变化时丢弃，不能因文件仍在目录里就重复执行。
3. 只将合法动作转换为现有 `DeviceGateway.move(direction, 1)` 的等价控制请求，由适配器再次校验；执行完获取新画面，再生成下一步计划。不要循环重放同一文件。

停止按钮/口令仍直接调用原停止接口，不等待模型；控制端在停止后必须丢弃待执行计划，后续恢复不能重放旧文件。生成 JSON 与播放语音都不代表机械臂已执行。`executed: false` 只是生成时事实，执行结果需要控制端另外记录，不能把它当完成回执。

## 获取方式与保留

同一电脑可直接读取上述目录；网页也提供「机械臂调整 JSON」预览和「下载控制计划」。`GET /api/ai/control-plans/{planId}` 仅允许生成该计划的本机浏览器会话下载，不向其他用户开放文件。

本进程保留最近 128 份计划，超过会删除该进程最早的计划；重启后不恢复旧下载会话。历史进程遗留文件不重新执行，可由组员清理归档。下载过期计划可用于检查内容，但不能再执行。生成目录已 Git 忽略，不提交运行记录。

## 前端对接

页面使用 `result.feedback` 播报，控制端只使用 `result.controlPlan.plan` 或对应 JSON 文件。模型连接时，助手的机位移动要求走计划生成，页面不直接发送 move；手动按钮、停止和快门继续走原入口。模型未连接时保留现有基础控制模式。LLM 参数违规会报错，不生成可执行计划。
